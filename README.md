# freee 勤怠レポート

freee 人事労務 API と連携し、**当月の勤怠データを自動取得して Excel レポートをワンクリックで生成**する Streamlit 製 Web アプリです。

---

## 主な機能

- freee アカウントで OAuth 認証（リダイレクト後に認可コードを自動取得）
- 所属会社を選択するだけで、当月分の勤怠データ（始業・終業・休憩・有給・半休）を自動取得
- 任意で **契約名** を入力してテンプレートに反映
- 所定のテンプレート「作業実施報告書」に転記し、氏名入りの Excel ファイルとしてダウンロード
- 60 名規模のチームでの同時利用を想定（セッションごとに独立したトークン管理・メモリ上でファイル生成）

---

## Excel への転記仕様

| セル | 内容 |
| --- | --- |
| K3 | 契約名（任意入力。空欄可） |
| K5 | 作業者の苗字（freee 登録の姓） |
| L5 | 作業者の名前（freee 登録の名） |
| K8 | 対象月の初日（例: 2026/04/01） |
| L8〜 | 曜日（テンプレート側の数式で自動表示） |
| M8〜 | 開始時刻 |
| N8〜 | 終業時刻 |
| O8〜 | 休憩時間 |
| H8〜 | 備考（有給・半休の場合に自動記載） |

---

## 有給・半休の自動判定

freee API のレスポンスをもとに有給・午前休・午後休を判定し、備考欄と勤怠時刻欄に以下を出力します。

| 状態 | 備考 | 開始-終業 | 休憩 |
| --- | --- | --- | --- |
| 全日有給 | 「有給取得」 | 転記事項なし | 転記事項なし |
| 午前休 | 「午前休取得」 | 打刻時刻を転記 | 休憩時間（無ければ 0.0） |
| 午後休 | 「午後休取得」 | 打刻時刻を転記 | 休憩時間（無ければ 0.0） |
| 通常勤務日 | 自動なし（祝日のみテンプレート側で表示） | 打刻時刻を転記 | 合計休憩時間 |

> ⚠️ 有給・半休は freee 側で **「申請 → 承認」が完了している** 必要があります。承認待ちのデータは API では取得できません。

---

## 使い方

1. 画面の **「freee 認証ページを開く」** をクリック
2. freee でログインし、認可を実行（リダイレクト後は自動で認証完了）
3. 対象会社を選択
4. 必要に応じて **契約名** を入力（空欄可）
5. **「データ取得 & Excel 作成」** をクリック
6. 生成された Excel を **「Excel をダウンロード」** で取得

---

## 同時利用時の安全性（最大60名規模対応）

複数ユーザーが同時に利用してもデータが混在しない設計になっています。主な仕組みは以下のとおりです。

### 1. 認証トークンはセッションごとに完全分離
freee の OAuth トークンは `st.session_state` に保存されます。Streamlit はユーザーごとに独立したセッションを持つため、A さんのトークンを B さんのセッションが参照することはありません。

### 2. Excel は各ユーザーのメモリ上で個別に生成
テンプレート Excel は **読み込み専用** で、ディスクに書き戻されません。各ユーザーの編集は Python のメモリ上のオブジェクト（`openpyxl` の `Workbook`）に対して行われ、最終的に `BytesIO`（ユーザーごとに独立したメモリバッファ）へ保存され、ブラウザに直接ダウンロードされます。共有ファイルを介さないため、上書き・混在は構造上発生しません。

### 3. テンプレートのキャッシュ化でファイルロック衝突を回避
テンプレート Excel は起動時に 1 度だけバイト列としてメモリへ読み込み、`@st.cache_resource` で全セッションが共有します。アクセスごとにファイルを開かないため、運用中にローカルでテンプレートを開いていてもアプリの動作に影響しません。

### 4. freee API 取得を並列化＋自動リトライ
1 ユーザーあたり最大 31 日分の勤怠取得を `ThreadPoolExecutor`（4 並列）で同時実行し、体感取得時間を大幅に短縮しています。`requests.Session` には `Retry`（最大 3 回・指数バックオフ・`Retry-After` ヘッダ尊重）を設定しており、429（レート制限）や 5xx の一時障害から自動回復します。同時利用が集中しても安定して取得できます。

### 5. 1 ユーザーあたりの処理は他ユーザーから独立
各セッションは独自の `Workbook` インスタンスと `BytesIO` を持ち、API 呼び出しのレスポンスもセッション内で閉じています。並列処理に伴う共有変数の書き込みは行われていないため、データ競合は発生しません。

> ℹ️ Streamlit Cloud 無料プラン（メモリ 1GB）で運用する場合、同時 30 名超のアクセスが恒常的に発生するとリソース不足になる可能性があります。その規模が見込まれる場合は有料プランや別ホスティングへの移行をご検討ください。
